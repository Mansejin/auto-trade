# 크루 협업 프로토콜

`.crew/`는 AI 크루의 공용 작업 공간이다. 에이전트끼리는 직접 대화할 수 없으므로 이 폴더의 파일로 일을 주고받고, 기억을 남긴다.

## 파일
- `board.md` — 작업 보드. 모든 요청·배정·상태가 여기 있다.
- `memory/<에이전트 이름>.md` — 에이전트별 기억. 다음에 호출될 때 이어서 일하기 위한 노트.
- `log.md` — 서브에이전트 실행 기록. 훅이 자동으로 남긴다(시간, 에이전트, resume ID, 대화 파일).
- `chats/<에이전트>-<ID 앞 8자>.md` — 서브에이전트 대화 전문(요청과 답). 훅이 자동 저장한다.

## 시작할 때
1. 이 파일, `memory/<내 이름>.md`, `board.md`에서 `to: <내 이름>`인 작업을 읽는다.
2. 이번에 맡은 작업의 상태를 `doing`으로 바꾼다.
3. 선행 작업의 산출물(참고 경로)을 읽는다. 앞선 대화 내용은 모른다고 가정한다.

## 끝날 때
1. 작업 상태를 `done` 또는 `blocked`로 바꾸고, `- 결과:` 줄에 결과 한 줄과 산출물 경로를 적는다. `done`만 `- [x]`로 표시하고 `blocked`는 `- [ ]`로 둔다.
2. `memory/<내 이름>.md`에 추가한다: 날짜, 한 일, 내린 결정과 이유, 다음에 알아야 할 것. 50줄을 넘으면 오래된 항목을 요약해 줄인다.
3. 다른 역할의 도움이 필요하면 `board.md`에 새 작업을 올린다.

## 작업 형식
```
- [ ] T-007 | to: code-reviewer | from: frontend-dev | open | 체크리스트 컴포넌트 리뷰
  - 참고: site/main.js, docs/crew/proposal/design.md
  - 완료 기준: Blocker/Major 없음
  - 결과: (끝낸 쪽이 채움)
```
- 상태: `open` → `doing` → `done` / `blocked`
- `to`: 에이전트 이름, `lead`(팀장이 판단), `user`(사용자 결정 필요). `to: user` 작업은 완료 기준 없이 결정할 내용만 적어도 된다.
- ID는 보드의 마지막 번호 + 1
- 자동 진행(`auto: on`)은 `open`이면서 `to`가 `user`가 아닌 작업만 센다. `blocked`와 `to: user`는 사용자가 풀 때까지 그대로 둔다.

## 협조 요청 규칙
- 요청은 보드에 쓴다. 받는 쪽은 내 대화를 모르니 파일 경로, 이유, 완료 기준을 작업에 적는다.
- 짧은 확인(리뷰 한 번, 수치 확인)은 서브에이전트로 직접 불러도 된다(중첩은 2단계까지). 그래도 보드에 `done` 작업으로 남긴다.
- 사용자 결정이 필요하면 `to: user`, `blocked`로 올리고 그 작업은 멈춘다.
- 담당 범위 밖 파일은 고치지 않는다. 필요하면 담당자에게 작업을 올린다.

## 읽기 전용 에이전트
`code-reviewer`, `security-auditor`, `yt-content-reviewer`는 파일을 쓸 수 없다. `doing` 전환은 팀장이 위임 전에 해 준다. 보고 끝에 아래 블록을 남기면 팀장이 반영한다(새 작업의 ID와 `from`은 팀장이 채운다).
```
### crew-update
- board: T-007 done — 판정 수정 후 승인, Major 1건
- board-add: to: frontend-dev | Major 1건 수정 | 참고: docs/crew/proposal/review.md | 완료 기준: 재리뷰 승인
- memory: 이 프로젝트는 localStorage 키에 버전 접미사를 붙인다
```
