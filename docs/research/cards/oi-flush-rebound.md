# 카드: oi-flush-rebound (미결제약정 급감 하락일 → 2일 반등)

우물: OI·청산 (1/2) · 상태: frozen 2026-10-08 · 보드 T-028

## 한 줄 원칙
하루에 미결제약정이 크게 줄면서 가격이 빠지면 강제청산이 끝난 것이니, 이틀 산다.

## 왜 돈이 나오나
- 가격 하락 + 미결제약정(OI) 급감 = 레버리지 롱이 청산 엔진에 의해 시장가로 강제 정리된 날이다. 청산 매도는 가격을 보지 않고 나오므로 적정가 아래로 밀어낸다.
- 손해 보는 쪽: 강제청산당한 레버리지 롱(가격 불문 시장가 매도). 그 물량을 받아주는 쪽이 유동성 공급 대가를 가져간다.
- 왜 안 사라지나: 청산 연쇄는 급락 한복판에 오고, 추가 하락 위험을 지고 받아줄 자본이 그 순간 가장 부족하다(마켓메이커도 리스크 한도를 줄인다). 이벤트가 몰려 나와 수익이 고르지 않아 대형 자금이 상시 대기하지 않는다.
- 기존 기각과 다름: `BTC dump sweep fade R3`(15m 가격 급락 페이드, KILL)는 가격만 봤다. 이 카드는 **포지션이 실제로 청산됐다는 비-OHLCV 증거(OI 감소)** 를 요구하고, 아래 "가격만 조건" 비교로 OI가 정보를 더하는지 직접 반증한다.
- 청산 이력 자체는 무료 장기 데이터가 없다(Binance 청산 스트림은 실시간뿐). 그래서 OI 일간 변화를 대용으로 쓴다.

## 데이터
| 시계열 | 무료 출처 (인증 없음) | 기간 | 카탈로그 |
|---|---|---|---|
| Binance USDT-M OI (5분 `sum_open_interest`) | `https://data.binance.vision/data/futures/um/daily/metrics/<SYMBOL>/` (zip) | 2021-12 전후 ~ (quant-data 확인) | **없음 → quant-data** |
| (대안) Bybit OI 일간 | `GET https://api.bybit.com/v5/market/open-interest?category=linear&symbol=BTCUSDT&intervalTime=1d&startTime=..&endTime=..&limit=200` | 시작 시점 확인 필요 | **없음 → quant-data** |
| Binance 무기한 일봉 BTC/ETH | `binance_perp_1d` | 2019-09 ~ | 있음 |
| Binance 무기한 일봉 SOL | `fapi/v1/klines?symbol=SOLUSDT&interval=1d` | 2020-09 ~ | **없음(SOL만 추가)** |
| Upbit KRW-BTC/ETH/SOL 일봉 (현물 실행) | `upbit_krw_1d` | 2017-09 ~ | 있음 |

일간 OI = UTC 00:00 시점 값. ΔOI_D = OI(D+1 00:00) / OI(D 00:00) − 1. 데이터 준비: **부분. OI 이력은 quant-data가 받아야 한다.** Binance REST OI 이력은 30일뿐이라 쓰지 않는다.

## 규칙 (하이퍼 2, 값 고정)
- 유니버스: BTC, ETH, SOL (무기한 거래대금 상위 3, 고정).
- 신호: UTC D일 ΔOI가 **train 구간 코인별 하위 5%** 이하 **그리고** D일 무기한 수익률 < 0. 임계값은 train에서 한 번 계산해 고정하고 OOS에서 다시 계산하지 않는다.
- 진입: D+1 00:00 UTC 시가 롱(= 업비트 09:00 KST 일봉 시가). 청산: **2일** 보유 후 시가. 손절 없음.
- 같은 코인 보유 중 신호 재발생은 무시(비중첩). 코인별 같은 명목 1배.
- 하이퍼: 분위 5%, 보유 2일.

## 예상 거래 수
3코인 × 365일 × 5% × (하락일 비율 ~0.7) ≈ 38건, 연속일 묶임을 빼면 **연 25~35회**. 빈도는 분위수로 정해지므로 시장 국면에 덜 흔들린다.

## 기각 기준 (사전)
- 분할: OI 시작 ~2023-06 train / OOS 2023-07~2026-09 고정. train이 18개월 미만이면 임계값 계산은 그대로 하고 결과에 "짧은 train" 표기.
- OOS 거래당 평균 수익 ≤ 0 → KILL.
- 수수료 2배(Upbit 편도 0.05%×2, Bitget 실행 시 0.06%×2) + 슬리피지 편도 5bps(SOL 10bps) 후 OOS PF < 1.1 → KILL.
- 전체 거래 < 30회 → INCONCLUSIVE. OOS 연환산 < 24회 → 빈도 미달 표기.
- 무작위 1,000회: 같은 코인·같은 건수의 무작위 날짜 2일 롱 → OOS 평균이 95백분위 미만이면 KILL.
- **OI 정보 검증(핵심)**: "D일 수익률이 train 하위 5% 이하"만으로 같은 규칙을 돌린 가격만 버전보다 OOS 평균이 높지 않으면 KILL. OI가 가격 이상을 말해주지 않으면 이미 죽은 덤프 페이드와 같다.
- 코인 부호: 3개 중 2개 이상 OOS 평균 부호가 반대면 KILL.
- B&H 대비: 노출일당 수익·Sharpe가 같은 코인 B&H보다 낮으면 KILL.

## SMA200과 결합
- **독립 슬리브**(별도 자본, 롱만). 하락 청산은 약세장에 더 자주 나오므로 SMA200으로 끄면 표본 절반이 사라진다. 주 판정은 게이트 없이 한다.
- SMA200 위/아래 별 성과는 보고만 한다. SMA200 아래 구간에서 PF < 1이면 "CORE 현금 구간 사용 불가" 표기(운영 정보, 게이트 추가 아님).
- 실행 메모: SMA200 위에서는 CORE가 이미 BTC 100%라 같은 계좌로는 추가 노출이 안 생긴다. 별도 자본이 필요하다. SMA200 아래에서는 CORE의 놀고 있는 원화를 쓸 수 있다.

## 실행 가능성
- Upbit 현물: 롱 전용 규칙이라 그대로 가능(KRW-BTC/ETH/SOL). 신호는 Binance OI, 체결은 업비트 09:00 KST.
- Bitget USDT-M: 1배 롱 가능. 펀딩 지급 반영 필요(하락 직후는 펀딩이 낮거나 음수라 대체로 유리).

## 판매 각도
"청산 끝 알림" — 레버리지 청산이 몰린 다음 날 아침 한 번 알리는 공포장 정보 채널(월 2~3회).
